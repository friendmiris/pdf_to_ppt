# SlideCraft · PDF → 편집 가능한 PPT 웹앱

PDF 여러 개를 업로드하여 **각각의 `.pptx`** 와 **전체 통합 `.pptx`** 를 한 번에 제작하고 **ZIP** 으로 다운로드하는 Vite 기반 정적 웹앱입니다.

## 1. 설치 및 실행

**필요 환경:** Node.js 20.19+ 또는 Node.js 22.12+ / npm

```bash
npm install
npm run dev
```

터미널에 표시된 주소(일반적으로 `http://localhost:5173`)로 접속합니다.

## 2. Vercel 배포 (GitHub 연결)

1. 이 폴더의 모든 소스 파일을 GitHub의 **새 저장소**에 업로드합니다. `node_modules` 폴더는 올리지 마세요.
2. [vercel.com/new](https://vercel.com/new) → **Import Git Repository** 에서 해당 저장소를 선택합니다.
3. Framework Preset은 **Vite**, Build Command `npm run build`, Output Directory `dist`로 설정합니다. (`vercel.json`에 설정되어 있습니다.)
4. **Deploy**를 누르면 자동으로 주소가 생성됩니다. 다음 업데이트 때도 GitHub에 코드를 반영하면 자동 재배포됩니다.

또는 Vercel CLI:

```bash
npm install
npm run build
npx vercel --prod
```

## 3. 실제 사용 방법

1. PDF 파일 1~30개 선택 (파일당 최대 200페이지, 총 1,000페이지, 개별 200MB/총 500MB 제한)
2. 이미지 표까지 편집하려면 **이미지 표 → 편집 가능한 PPT 표** 영역에서 PDF·페이지를 선택하고 **페이지 표시**를 누릅니다.
   - 표 전체를 마우스로 드래그하여 선택
   - 행/열 개수 지정 (예: GAAT 5페이지 표는 6행 × 3열)
   - **표 글씨 OCR 인식** 실행 후 셀 내용을 교정
   - **이 표를 편집형으로 저장** 누르기 (여러 페이지에서 반복 가능)
3. **변환 시작하기** 클릭
4. 변환 완료 후 **모든 결과 ZIP 다운로드** 버튼 클릭
5. ZIP 안에 `개별_PPT/`, `통합_PPT/전체_통합_01.pptx` 등이 수록 (통합본 500장 단위 분할)
6. 사이트에서 **분할된 통합 PPT를 각각 다운로드**할 수도 있음

## 4. 프로그램 내 처리 한도 및 대량 처리 안정화

| 구분 | 앱 설정 제한 |
|---|---|
| 입력 PDF 개수 | 최대 30개 |
| PDF 1개 페이지 | 최대 200페이지 |
| 한 번의 변환 전체 페이지 | 최대 1,000페이지 |
| PDF 1개 파일 크기 | 최대 200MB |
| 전체 PDF 크기 | 최대 500MB |
| 1개 처리 묶음 | 5개 PDF씩 순차 처리 (실제로는 하나씩 열어서 처리) |
| 통합 PPT | 최대 500장씩 분리 출력 |

- 파일·페이지별 진행률과 변환 실패 항목 표시, 성공 파일 계속 변환.
- PDF 1개씩 열고 페이지별로 PDF 객체/캔버스를 정리하여 메모리 부담 경감.
- 통합본은 500장 단위로 PPTX 직렬화, 개별 PPT 및 합본들을 ZIP에 저장.
- 메모리 특성상 **제한값에서의 안정적 처리까지 검증된 것은 아닙니다.** 특히 500MB 파일이나 1,000페이지는 컴퓨터 사양에 따라 변환 또는 ZIP 생성이 실패할 수 있습니다.
- **다운로드는 변환 완료 후 버튼을 눌러 실행**합니다. 대용량 ZIP 다운로드가 안 되면 통합본 개별 다운로드를 이용하세요.

## 5. 편집 가능 범위 및 기술적 제약 (중요)

- **편집 가능:** PDF에 문자 데이터로 존재하는 글씨는 대부분 PowerPoint 텍스트 상자로 변환됩니다.
- **배경 요소:** 사진, 자동 처리되지 않은 표, 벡터 도형, 복잡한 그래픽은 이미지로 유지됩니다. **표 편집기에서 영역을 지정하고 셀을 교정한 표는 네이티브 PPT 표로 생성되며 셀 글씨·색·크기·행·열을 수정할 수 있습니다.**
- **스캔본:** 본문 전체 자동 OCR은 제공하지 않습니다. **선택한 표 영역**만 한·영 OCR을 지원하며 사용자가 행·열 및 결과를 확인해야 합니다. 초회 OCR 시 언어 데이터를 인터넷으로 내려받으므로 네트워크가 필요합니다. 복잡한 병합 셀은 자동 인식되지 않습니다.
- **정확도:** 원본 글꼴, 텍스트 색상, 줄 간격, 회전 텍스트, 단어 간격, 도형 및 배경이 완벽히 일치하지 않을 수 있습니다. PowerPoint에서 후편집을 권장합니다.
- **기능상 안전장치:** PDF.js의 일반 캔버스 글씨 그리기를 비활성화하여 배경에 글씨가 중복 인쇄되는 현상을 최소화합니다. 특수 폰트와 문자 윤곽선 PDF는 원본 글씨가 이미지에 남을 수 있습니다.
- **용량:** 서버 업로드가 없으므로 Vercel Function 요청·응답 제한을 회피하지만, 사용자의 PC 메모리가 부족하면 대용량 작업은 실패할 수 있습니다. 큰 파일은 여러 번 나눠 실행하세요.
- **개인정보:** 변환은 클라이언트 브라우저 안에서 실행됩니다. 사용자가 넣은 PDF 문서는 서버로 보내지지 않습니다. 최초 JS/CSS 리소스 로딩은 네트워크를 사용합니다.
- **파일 순서:** PDF를 추가한 순서대로 통합 슬라이드가 만들어집니다. 중복 파일 이름은 자동으로 `_2`, `_3`이 붙습니다.
- **페이지 비율:** 통합 PPT의 슬라이드 크기는 16:9, PDF 원본 페이지는 가운데 비율 유지로 들어갑니다.

## 6. 기술 구성

| 도구 | 역할 |
|---|---|
| Vite | 웹앱 빌드와 정적 배포 |
| PDF.js (`pdfjs-dist`) | PDF 페이지 파싱/렌더링/텍스트 추출 |
| PptxGenJS | 편집 가능한 PPT 텍스트 + 페이지 비주얼 |
| JSZip | 개별 PPT와 통합 PPT ZIP 묶기 |
| Tesseract.js | 선택한 이미지 표의 한·영 OCR (사용자 확인 필요) |

백엔드, API 키, DB, 결제 설정이 필요하지 않습니다.

## 7. 테스트 / 유의 사항

```bash
npm run build
```

빌드 후 `dist`를 Vercel에 배포할 수 있습니다. 다양한 유형의 PDF를 실제 변환해 보고 글씨 중복, 줄바꿈, 배경을 확인하세요. 이 프로젝트는 **선택한 표 영역의 OCR**을 지원하지만, PDF 속 모든 표를 자동으로 완벽하게 인식하거나 그림/도형을 완전 재구성하는 솔루션은 아닙니다.

## 8. 실제 PDF로 수행한 변환 검증 (2026-11-08)

검증 파일: `경북기계명장고 GAAT 수업자료 1일차.pdf` (59페이지, 16:9).

- `tools/convert_pdf.py` 로 59장 개별 PPT 및 59장 통합 PPT 생성 완료
- 각 PPT에 편집 가능한 텍스트 상자 889개가 포함됨을 `python-pptx`로 확인
- LibreOffice에서 PPTX → PDF 재내보내기 성공 (59페이지)
- 원본 PDF 대비 한글 줄바꿈, 글꼴과 작은 텍스트의 위치 차이가 확인되어 일부 개선함
- **브라우저 앱의 npm 설치·Vite 빌드 및 Vercel 배포는 이 검증 환경에서 완료하지 못함.** 웹 UI의 실제 작동까지 검증한 것은 아님

로컬에서 같은 엔진 유형의 서버 독립 변환을 시험하려면 별도 Python 환경에서:

```bash
pip install pymupdf python-pptx
python tools/convert_pdf.py "input1.pdf" "input2.pdf" --output result.zip
```

이 Python 도구는 Vercel 웹앱이 호출하는 코드가 아니라 **별도로 테스트 가능한 대체 변환기**입니다.

## 9. 이번 개정본 검증 현황

- 제공한 59장 PPTX의 압축 구조/슬라이드 수/편집 텍스트 상자 존재 검증: 통과.
- 브라우저 소스 main.js 및 converter.js에 대한 `node --check` 문법 검사: 통과.
- `npm install`은 본 제작 환경에서 제한 시간 내 완료되지 않아, **Vite 빌드 및 브라우저 실제 변환은 미검증**.
- Vercel 실제 배포도 미검증. 위 개정본의 30개/1,000페이지 대용량 처리는 설정상 한도이며 실측 성능이 아님.
